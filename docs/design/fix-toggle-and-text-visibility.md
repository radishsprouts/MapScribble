## 3. 決定1: 手書きモードの終了手段

### 3.1 推奨案（両方を行う）

**(A) Xaero / FTB の右上の切替ボタンを、オンの間も出し続けてトグルにする。**
**(B) ツールの帯の右端に、縦長の「終了」ボタンを足す。**

### 3.2 根拠

1. **(A) は、押した場所に戻れば終わるという期待に応える。** 利用者は右上のボタンを押して手書きモードに入る。同じボタンが消えるのは、トグルとしての一貫性（ヒューリスティクス4）に反する。JourneyMap では既に常設のトグルになっており（`ScribbleBridge.java:157`）、MOD 間で振る舞いが揃う
2. **(B) は、3つの地図 MOD すべてで出口を帯の中に置ける。** (A) だけだと、JourneyMap 以外では出口が右上1か所、しかも位置はアダプタ任せ（`MapAdapter.toggleButtonX/Y`）で、地図 MOD のボタン群に紛れる。さらに**帯はドラッグで動かせる**ので、帯を右上へ動かすと切替ボタンに重なる。出口が帯そのものに付いていれば、帯がどこにあっても出口が見える（ヒューリスティクス3「出口は見つけやすく」）
3. 帯に置けば、終了がキーボードのキー（`key.mapscribble.toggle_mode`、既定は未割り当て）だけに依存しなくなる

### 3.3 落とした案と理由

| 案 | 落とした理由 |
|---|---|
| 右上のボタンを常設するだけ（帯に足さない） | 帯を右上へ動かすと、帯が切替ボタンを覆う（または覆われる）。出口が帯の外にある限り、帯の位置によっては見えなくなる |
| 帯に終了ボタンを足すだけ（右上は今のまま） | オンにした場所からボタンが消える非対称が残り、「押した所に戻れば戻れる」期待に反したままになる |
| 終了を帯の**左端**（ツール群の前）に置く | 既存の全セルの座標が 22px ずれる。「必要が無いのに既存の配置を変えない」に反する |
| 終了ボタンのアイコンを右上と同じ鉛筆にして「選択中（青）」で示す | 帯は手書きモード中しか出ないので、青い鉛筆は常に青く、状態を示す情報量がゼロ。しかもツール群と同じ青い面になり「選べるツールの一種」と誤読される |
| 帯の幅を広げずに、既存ボタンを詰めて場所を作る | 上段・下段とも右端まで埋まっており（1章）、詰めるには既存の全セルを動かすしかない |

### 3.4 帯のレイアウト（数値で確定）

**帯の大きさ: 235×41（幅のみ 208 から +27。高さは変えない）。**

幅を広げる理由（「むやみに広げない」への説明）: 1章のとおり帯の中に 20×20 のボタンを入れる空きが 1px も無く、既存のボタンを1つも動かさずに出口を足すには右端へ継ぎ足すしかない。+27 は「区切り線までの余白3＋区切り1＋余白2＋ボタン20＋右の余白3」の合計で、余白は既存の群の間隔と揃えた。最小の GUI（320×240）でも、帯を既定位置 (28,44) に置いたときの右端は **GUI x 263** で、JourneyMap の右列（x 296 以上）に 33px の余裕が残る（`ui-design.md` 3.1 の実測による位置）。

**追加する要素（帯の左上を原点とする座標）**

| 要素 | 位置 (x, y) | 大きさ | 中身 |
|---|---|---|---|
| 区切り線（新） | (210, 5) | 1×31 | `#FFFFFF` 25%（既存の区切り線と同じ `SEPARATOR = 0x40FFFFFF`） |
| 終了（新） | (212, 3) | **20×35** | アイコン `tool/exit.png` 16×16 を (214, 12) に置く（ボタン内で x は中央、y は上9・下10） |

終了ボタンだけ上下2段にまたがる縦長にした理由: (1) 下段の色の見本（右端 207）より右に 20×13 の空きができるのを避け、帯の右端をまっすぐに揃えるため、(2) 他のどのボタンとも形が違うので、押せる物として最初に目に入るため（Fitts の法則の意味でも、出口は大きいほどよい）、(3) 押せる領域が 20×35 GUI px（GUI 倍率2で 40×70 画面ピクセル）になり、WCAG 2.5.8 の 24×24 を余裕で満たすため。

**既存のセル・区切り線の座標は1つも変えない。** 変更前後の全セルの座標は `docs/design/mockups/fix-toggle-and-text-visibility.html` の「7. 帯の座標」の表にまとめた（「変更なし」と書いた行がそのまま残すもの）。実装後に `ui/BandLayout.java:48-77` を読み直し、既存のセル（ツール5・元に戻す 118・やり直す 140・文字の表示切替 165・メモの表示切替 186、下段の太さ・文字の大きさ・色、既存の区切り線4本）がすべて変更前と同じ座標であることを確かめた（2026-10-27）。

### 3.5 終了ボタンの見た目

面・縁・アイコンの色は**既存の帯のボタンと同じトークン**を使う（`ui-design.md` 3.1「ボタンの状態」の表）。出口を特別な色で目立たせない（帯の中で色の意味を増やすと、選択中の青との区別が弱まるため）。

| 状態 | 面 | 縁 1px | アイコン |
|---|---|---|---|
| 通常 | `#FFFFFF` 15% | `#FFFFFF` 45% | `#E6E6E6` |
| ホバー | `#FFFFFF` 30% | `#FFFFFF` 70% | `#FFFFFF` |
| 押下中 | `#FFFFFF` 45% | `#FFFFFF` 100% | `#FFFFFF` |
| 無効 | **無い**（終了ボタンは、読み込み中・保存失敗・地図の準備中のどの状態でも押せる） | | |

選択中（青い面）の状態は持たない。ツールではないため。

**ツールチップ**（バニラのツールチップ。1行目 白、2行目 灰 `#A0A0A0`）

| 1行目 | 2行目 |
|---|---|
| 手書きモードを終える | ツールの帯を閉じ、地図の操作に戻ります |

1行目は既存キー `mapscribble.button.toggle.on` を流用する（右上ボタンのオン時と同じ文言でよい。内部的一貫性）。2行目は新しいキー `mapscribble.button.toggle.on.desc`（6章）。

**押したときの挙動**: `state.toggleMode()` を呼ぶ（`ToolBand.click` の `switch` に `case EXIT -> state.toggleMode();` を足す。`ui/ToolBand.java:128-137`）。クリック音は既存どおり `GuiCompat.playButtonClickSound()` が鳴る。描きかけの線がある状態で押された場合は、`ScreenMapHost.onScreenClose` と同じく `controller.cancelStroke()` を呼んで捨てる（描きかけが残らないようにする。既存の「画面を閉じた時に描きかけを捨てる」修正と同じ扱い）。

### 3.6 右上の切替ボタンの見た目（Xaero / FTB）

**オン・オフの両方で描く。** 位置・大きさは現状のまま（`MapAdapter.toggleButtonX/Y` が返す位置に 20×20）。

| 状態 | 面 | 縁 1px | アイコン `tool/toggle.png` | ツールチップ |
|---|---|---|---|---|
| オフ・通常 | `0xCC181818` | **`0xFFA8ADB4`**（旧 `0xFF555555` から変更） | `#E6E6E6` | — |
| オフ・ホバー | `0xEE303030` | `0xFFFFFFFF` | `#FFFFFF` | 「手書きモードにする」＋灰「ツールの帯を出して、地図に手書きできます」 |
| オン・通常 | `0xFF2E7DD7`（帯の「選択中」と同じ） | `0xFFFFFFFF` | `#FFFFFF` | — |
| オン・ホバー | `0xFF4A93E4` | `0xFFFFFFFF` | `#FFFFFF` | 「手書きモードを終える」＋灰「ツールの帯を閉じ、地図の操作に戻ります」 |

- **縁の色を変える理由**: 旧 `#555555` は、地図が明るい地形（雪原・砂漠）のときに面 `#181818` 80% と重なった `#3D3D3D` 相当に対して **1.46:1** しかなく、WCAG 1.4.11（文字以外の UI 部品は 3:1）を満たしていなかった。`#A8ADB4` にすると面に対して **4.6:1** になる（計算は 4 章）。これは今回の依頼「オンとオフでの見え方の違い」を決める範囲に含まれる
- **オンを色だけで示さない**: 青い面に加えて、白い縁・ツールチップの文言・そもそも帯が出ていること、の3つで状態が分かる
- **オフの時のツールチップの文言が逆になっている不具合を直す**（`map/ScreenMapHost.java:243-246` が、オフのボタンに `mapscribble.button.toggle.on` を出している）。オフは `...toggle.off`、オンは `...toggle.on` を出す

**描画順とクリックの優先**

- 描画は「メモ → **切替ボタン** → 帯」の順に変える（現状は帯の後に切替ボタン。`map/ScreenMapHost.java:213-221` の2つのブロックを入れ替える）。帯をドラッグして切替ボタンに重ねたとき、**手前に描かれる物と反応する物を一致させる**ため
- クリックは現状どおり帯（`scribbleUi.onMouseClick`）を先に見る（`map/ScreenMapHost.java:284`）。そのうえで、オンの時も切替ボタンの当たり判定を見るようにする（`map/ScreenMapHost.java:275-281` の `if (!state.isModeOn())` の外へ出す）

### 3.8 帯を画面内に収める補正（2026-10-27 追加。実装で追加されたものを設計として認める）

実装で `ui/ScribbleUi.java:144-157` に `keepBandOnScreen` が追加された。**設計として認める。** 以下をこの機能の仕様とする。

| 項目 | 仕様 |
|---|---|
| 目的 | 帯の幅が 208 から 235 へ広がったため、**旧バージョンで保存した右寄りの位置**や、窓を小さくした後の位置では、帯の右端（＝終了ボタン）が画面の外に出て、出口が見えなくなる。これを防ぐ |
| 掛ける条件 | 帯を**ドラッグしていない間**だけ（`band.isDragging()` が真なら何もしない） |
| 補正の内容 | 帯の左上を x は 0〜`max(0, 画面幅 − 235)`、y は 0〜`max(0, 画面高 − 41)` の範囲へ丸める。範囲外だった時だけ位置を書き換えて保存する |
| 画面が帯より狭い場合 | 上限が 0 になるので左上 (0,0) に寄せる（右端・下端がはみ出すが、少なくとも出口のある側ではなく左上が残る。GUI は最小でも 320×240 なので、幅 235 の帯では通常起きない） |

**なぜ必要か（別の形を採らなかった理由）**

1. 出口（終了ボタン）は帯の**右端**にあり、はみ出す時に最初に消えるのがその出口である。ヒューリスティクス3「出口は見つけやすく」が、帯の位置の保存という既存機能のせいで壊れる。補正しないと、旧バージョンから更新した利用者だけが出口を失う
2. 「ドラッグ中は補正しない」のは、ドラッグの手応え（指に付いてくること）を壊さないため。離した次のフレームで収まる
3. 落とした案: (a) 更新時に一度だけ位置を初期化する → 利用者が決めた位置を理由も見せずに捨てることになる。(b) はみ出した時に説明の行で知らせて利用者に直させる → 説明の行は状態表示に使っており（`ui-design.md` 3.1）、しかも直す操作（ドラッグ）が画面外で掴めない場合がある。(c) 補正せず終了ボタンだけ帯の左端へ移す → 既存の全セルの座標が動く（3.3 の表と同じ理由で落とした）
4. この補正は**位置の保存と矛盾しない**。利用者が画面内に置いた位置は一切変えない（範囲内なら書き換えが起きない）

## 4. 決定2: 文字の表示切替の対象

### 4.1 推奨案

**すべての文字（囲みに付けた文字・線に付けた文字・文字メモの文字）を対象にする。** 社長の報告のとおりでよい。

### 4.2 根拠（なぜ「すべて」でよいか）

1. **ボタンが「文字」としか名乗っていないのに一部にしか効かないのは、ラベルと効き目の食い違いである。** 利用者から見て予測できない（ヒューリスティクス4）
2. **JourneyMap 自身の作法は「ボタン1つ＝その種類の全部」**（2章。Monsters ボタンは全モンスター、Grid は全グリッド）。一部にだけ効くボタンは JourneyMap に無く、そこへ例外を1つ持ち込むことになる
3. **この切替の目的は「形だけを見たい」こと。** 地形や自分の囲みの輪郭を確かめるために文字を退けるのだから、退ける対象が囲みの文字だけでは目的を果たさない
4. 種類ごとに分ける案（囲み／線／文字メモで3ボタン）は落とした。帯にボタンが2つ増えて幅がさらに +44 必要になるうえ、選ぶ手数が増える（Hick's Law）。利用者はメモを「囲み・線・文字」という内部の種別ではなく「自分のメモ」として捉えており、文字だけを種別で割る理由が無い

### 4.3 文字メモ（TEXT）の扱い: 印を残す

文字メモは文字が本体なので、文字を隠すと**完全に見えなくなる**。これは次の2つの問題を起こすため、**印を残す**。

- 消えたのか不具合なのか分からない（ヒューリスティクス1「状態の可視化」）
- 当たり判定は文字の矩形のままなので（`draw/HitTester.java:56-67`）、「見えないのにクリックが当たる」「見えているのに選べない」状態になる

**印の仕様**

**寸法の数え方（2026-10-27 に確定）**: この表の「大きさ」は**菱形の本体（塗り）の寸法であり、縁を含まない**。縁は本体の外側へ 1 画面ピクセル付くので、縁を含めた外形は本体より各方向 1 ピクセル大きい。全画面では本体が中心から各方向 4 画面ピクセル（対角 8）、縁を含めた外形は対角 10 になる。**実装の `MARK_RADIUS` は 4 のままとする（3 に変えない）。**

### 4.5 アイコンの差し替え

既存の `region_text_visible.png` / `region_text_hidden.png` は、名前も絵柄も「区画の文字」を指しているので差し替える。あわせて、**ツールの「文字」ボタン（`tool/text.png`＝大きな A）と見分けがつく絵柄**にする。モックアップで並べて確かめたところ、A だけでは隣の群でも紛らわしかった。

**枠は「点線」で確定する（2026-10-27）。** 当初は「線2px・間隔2px の破線」と書いたが、生成・加工の結果は3候補とも **1画素オン・1画素オフの点線**になった。実物（`art/src/text_visible_zoom.png` を 2026-10-27 に確認）では、外周に沿って点が等間隔に並ぶ枠と、中央の A が分かれて見える。**これを許容し、仕様の数値を実物に合わせる。**

許容する理由:

1. **16×16 では、2:2 の破線も 1:1 の点線も「点の並びの枠」としてしか見えない。** 枠の一辺が 14 画素しかないので、破線の周期の違いは利用者の見分けの対象にならない。図柄の目的（地図上の文字の背景＝ラベルの矩形を連想させ、枠なしの大きな A である `tool/text.png` と見分けさせる）は点線でも達成できる
2. **点線のほうが A との分離が保たれる。** 枠の画素が減るぶん、枠と A の間の透明な隙間が広く残り、16×16 で A が読める。分かりやすさの観点ではむしろ良い方向である
3. **撮り直しの損のほうが大きい。** 枠の周期だけのために撮り直すと、`text_hidden` が「`text_visible` を土台に斜線だけを貼り合わせる」方式（`art/asset-spec.md` の撮り直し手順）でそろえた A の一致をやり直すことになり、Dev-Art-Director が不採用の理由に挙げた「A が別物に見える」問題を再発させる risk のほうが、破線と点線の差より大きい。工数ではなく**成果物の品質**の判断である
4. 枠の画素が減ってもコントラストは変わらない（白 `#FFFFFF` のまま。帯の背景に対して 8.5:1。5章）

| # | ファイル | 用途 | 大きさ | 図柄 |
|---|---|---|---|---|
| 13 | `textures/gui/tool/text_visible.png`（`region_text_visible.png` を置き換え） | 文字の表示切替（表示中） | 16×16 | 外周に**1画素の点線の枠**（14×14、点 1px・間隔 1px。周期は 2 画素）、その中央に 8×10 程度の大文字「A」。枠と A の間に透明な隙間を残す。枠は地図上の文字の背景（黒 80% の矩形）を連想させ、「ラベルの表示」を表す |
| 14 | `textures/gui/tool/text_hidden.png`（`region_text_hidden.png` を置き換え） | 同（非表示中） | 16×16 | **13 の画像をそのまま土台にし**（枠・A は 13 と画素単位で同じ）、左上→右下の斜線（太さ 1px・10 画素、階段状、枠の画素と接しない）を重ねる。斜線を足す作法はメモの表示切替（`visible.png` / `hidden.png`）と揃える |

- #14 を「13 と同じ画素に斜線を重ねる」と決めたのは、この2枚が**同じボタンのオン・オフ**として交互に表示されるためである。A の形が変われば「文字が隠れた」ではなく「別の絵に変わった」と読まれる（Dev-Art-Director の不採用の理由と同じ）
- 斜線が A の脚・横棒と交差する画素で重なるのは許容する（既存の `hidden.png` の目と斜線でも同じ）

古い `region_text_*.png` は削除する（参照は `ui/ToolBand.java:57-58, 70-71`）。

## 9. アクセシビリティ要件

- **状態を色だけで示さない**: 右上ボタンのオンは「青い面＋白い縁＋ツールチップの文言＋帯が出ていること」、文字の表示切替は「アイコンの斜線＋ツールチップの文言」で分かる
- **コントラスト**: 文字以外の UI 部品はすべて 3:1 以上（5章の表）。今回、基準を満たしていなかった右上ボタンのオフの縁を直した
- **押せる領域**: 終了ボタン 20×35 GUI px（GUI 倍率2で 40×70 画面ピクセル）、右上の切替ボタン 20×20（同 40×40）。いずれも WCAG 2.5.8 の 24×24 を満たす
- **出口が画面外に出ない**: 帯を画面内へ収める補正（3.8）で、終了ボタンが常に画面内にある
- **キーボード**: 手書きモードの終了は、既存の `key.mapscribble.toggle_mode`（操作設定で割り当て可、既定は未割り当て）でもできる。今回のボタンは、そのキーに依存しない画面上の出口である
- **ドラッグでしかできない操作を作らない**: 終了も文字の表示切替もクリック1回でできる
- **アイコンの代替テキスト**: 新しいアイコン2種（exit・text_visible/hidden）とも、ホバーで文言が出る（AC-65・AC-77）

## 11. 自己評価（モックアップをブラウザで、GUI 320×240 相当と GUI 960×540 相当の両方で確認）

モックアップ `docs/design/mockups/fix-toggle-and-text-visibility.html` をブラウザで開き、1 GUI ピクセル＝2 CSS ピクセルの表示（最小の GUI 320×240）と、1 GUI ピクセル＝1 CSS ピクセルの表示（GUI 960×540）で見た。

1. **一目で分かるか**: 帯の画像だけを見て「左上の帯でツールを選んで地図に描く画面。右端の×で終われる」と言える。縦長の×は他のボタンと形が違うので、ツールの群と混ざらずに見つかる
2. **認知的ウォークスルー（手書きを終える）**
   - 終えようとする: 帯が出ていること自体がモード中の印
   - 正しい操作に気付くか: 帯の右端の×（他のボタンと形・大きさが違うので目に入る）と、右上の青いボタン（入った時と同じ場所）の2か所
   - 操作と結果を結び付けられるか: ホバーで「手書きモードを終える／ツールの帯を閉じ、地図の操作に戻ります」と文で出る
   - 操作の後に分かるか: 帯が消え、右上のボタンが青から暗い面に戻り、地図がドラッグで動くようになる
3. **10ヒューリスティクスで見つけた点**
   - **中→解消**: 右上の切替ボタンのオフの縁 `#555555` が、明るい地形（雪原・砂漠）の上で 1.46:1 しかなく、WCAG 1.4.11（3:1）を満たしていなかった（モックアップの雪原の見本で気付いた）→ 縁を `#A8ADB4`（4.6:1）に変更した（3.6・5章）
   - **中→解消**: 文字の表示切替のアイコン（A）が、ツールの「文字」（A）と紛らわしい。最初の案（A＋下線）では 16px で差が 1px しか出ない → 枠の中に小さな A、という絵柄に変えた（4.5）
   - **中→解消**: 最初のモックアップでは、終了ボタンのツールチップがボタン自身を覆っていた → ツールチップはカーソルの右下に出す前提で見本を直し、受け入れ基準（AC-65）にも「ボタン自身を覆い隠さない」を入れた
   - **中→解消（2026-10-27、実装後に発覚）**: 帯の幅を 208 から 235 へ広げたため、旧バージョンで保存した右寄りの位置では**出口（終了ボタン）が画面外に出る**。設計の抜けだった（帯の位置が保存されることは 1 章に書いていたのに、幅を変える影響を見ていなかった）→ 実装が入れた画面内への補正を設計として認め、3.8 と AC-83〜AC-85 を足した
   - **中**: 終了ボタンはアイコンだけで、常に見える文字のラベルが無い（NN/g「Icon Usability」）。帯の幅をこれ以上広げずに文字を置く余地が無く、既存の元に戻す・やり直す・表示切替も同じ扱いなので、2行のツールチップと×という慣例の強い図柄で補うことにした。帯の説明の行に出す案は、説明の行が選択中のツールと状態表示に使われており、ホバーで上書きすると状態の表示が隠れるため採らなかった
   - **低（2026-10-27）**: `text_visible` / `text_hidden` の枠が、仕様の破線（2:2）ではなく点線（1:1）になった → 16×16 では見分けの対象にならず、枠と A の分離はむしろ良くなるので許容し、仕様の数値を実物に合わせた（4.5）
   - **低**: 出口が2か所（帯の×と右上のボタン）あるのは重複だが、どちらも「トグルを押して戻る」「見えている出口から出る」という別の期待に応えている。地図 MOD によって出る場所が違うので、片方だけでは埋まらない
   - **高**: なし
4. **コントラスト**: 5章に計算値を書いた（WCAG の相対輝度の式。地図が最も明るい場合で計算）。新しく足した色はすべて 3:1 以上

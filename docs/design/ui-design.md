## 1. 目的・利用者・主要タスク

- 利用者: 無料サーバー（一般 `lis_world`・資源 `res_world`）で JourneyMap を使っているプレイヤー本人。メモは自分にだけ見える
- 主要タスク
  1. 全画面マップで手書きモードにして、区画をなぞって囲み、文字を付ける（主機能）
  2. 線を引く・文字だけを置く
  3. 描いたメモを消す・直す・元に戻す
  4. メモ全体を一時的に隠す／地図上の文字だけを一時的に隠す
  5. （0.4.0）1つのアドレスの裏で複数のサーバーへ振り分けられる接続先（プロキシ）で、サーバーごとにメモを分ける。分ける前に描いたメモを、今のサーバーのメモ帳へ移す
- 動線: 全画面マップ（JourneyMap）→ 右列の「手書き」ボタン（またはキー）→ ツールの帯が出る → 描く → 文字入力の画面 → 確定で地図へ戻る → 帯の終了ボタン（または右上/右列の手書きボタン）でモードを終える
- 動線（保存先）: 帯のメニューのボタン → メニュー「保存先…」→ メモの保存先の画面 → メモ帳を選ぶ・名前を変える・分ける前のメモを移す → 完了で地図へ戻る

### そこから採ったこと

- 右列は JourneyMap と他のアドオンのボタンが増える場所、上部・下部・左は JourneyMap の固定のボタンと表示行。**MapScribble の帯は、そのどれにも触れない左上の「上部ツールバーと表示行の下、左列の右」に置く**
- アイコンは JourneyMap に合わせて**白い単色の線画・透過**にし、状態の色はプログラムで乗せる
- 地図上の囲みは MapFrontiers と同じ「実線＋半透明の塗り＋中央の文字」にする（利用者が知っている見え方）
- アイコンだけにしないため、帯の外の説明の行に**選択中のツール名と操作の説明を常に文字で出す**（ツールチップだけに頼らない）
- 表示切替は JourneyMap の作法に合わせ、**1ボタン＝その種類の全部**にする（文字の表示切替は、囲み・線・文字メモのすべての文字が対象。2026-10-26）
- （0.4.0）帯には描く間に繰り返し押す物だけを置き、たまに使う物は**メニュー1つ→画面**の2段に送る。メニューの中にメニューを作らない
- （0.4.0）サーバーごとの保存先は「**メモ帳**」という名前の付いた入れ物として一覧で見せ、行をクリックして選ぶ（Xaero のサブワールドの選び方と同じ考え方）。分ける前のメモは隠さず、利用者が移すかどうかを選ぶ

## 3. 推奨案

### 3.1 ツールの帯（手書きモード中だけ表示）

**置き場所: 画面の左上、既定の原点 (x=28, y=44)、大きさ 256×41**（2026-11-17 に 235×41 から変更。0.10.0 までの最終形）。説明の行は帯の外に描く。位置は帯の左上から (3,44)。帯が画面の下端近くにある時は帯の上（3.1「説明の行の位置・背景・重なり」）。**利用者は帯の余白をドラッグして動かせ、位置は保存される**（`ui/ToolBand.java`）。ドラッグしていない間は画面内へ収める補正が掛かる（この節の末尾）。

根拠:
- Minecraft は GUI 座標が 320×240 未満にならないよう倍率を選ぶ。最小の 320×240 で、JourneyMap の各要素は次の範囲にある（実測からの見込み）。帯 (28..284, 44..85) は、キー一覧を除くどれとも重ならない
  - ロゴ: x 0..22, y 0..22 / 上部ツールバー: 中央、y 0..22 / 表示行: y 約24..34
  - 左列: x 0..24、縦中央（240 の時 y 約78..162）→ 帯は x 28 から
  - 右列: x 296..320 → 帯の右端 284（12px の余裕。プランの決まり 1 の上限 264 幅＝右端 292 の内側）
  - 下部ツールバーと表示行: y 206..240
  - キー一覧（Keys オン時）: 右下。**GUI の幅が 427 以上なら帯に届かない。幅 320（窓 640×480・倍率2）では、下部ツールバーを避けて上へ伸び、上端が y 約91・左端が x 約205 まで来る**（2026-10-21 に実機の画像で確かめた。行の数と幅は JourneyMap の版と言語で変わる）。**帯の下端は y 85 のまま（0.4.0 でも変えていない）なので、重なるかどうかは実機で測り直す**（未決事項。11章）
- `FULLSCREEN_RENDER_EVENT` は**ボタンより先に**呼ばれる（05章）。重なると JourneyMap のボタンが帯の上に描かれてしまうので、ボタンと重ならないことが必須
- 縦に並べる案は、最小の画面で高さが足りない（全要素で 200 を超える）ため落とした。色・太さを押して開く小窓にする案は、色を変えるたびに1手増え、小窓が左列に重なるため落とした

**状態ごとの帯の振る舞い**

- 読み込み中・地図の準備中・読み込み失敗: ツール・色・太さ・塗りは押せる（選んでおける）が、地図への描画・消しゴム・編集のクリックは何もしない（地図の移動も止めない＝ドラッグを取り消さない）。元に戻す・やり直すは無効。**終了ボタンと右上/右列の切替ボタン、メニューのボタンは、どの状態でも有効**
- メモを隠している時: 囲み・線・文字は描ける。**新しいメモを確定したら自動で表示に戻す**（描いたのに見えない、を防ぐ）。消しゴム・編集のクリックは「メモを表示してから選んでください」を出して何もしない
- 文字を隠している時: 囲みの輪郭・塗り・線はそのまま出る。文字メモは菱形の印になる（3.3）。描く・消す・直すはいずれも通常どおりできる
- 権限なし: この MOD はクライアントだけで自分のメモを扱うため、権限で操作を分ける場面は無い（サーバーの権限チェックも無い）

**帯の位置と、画面内への補正**（2026-10-27 追加。詳細と落とした案は `fix-toggle-and-text-visibility.md` 3.8）

- 帯は余白をドラッグして動かせ、位置は保存される。既定は (28,44)
- **ドラッグしていない間だけ**、帯の左上を x: 0〜`max(0, 画面幅 − 256)`、y: 0〜`max(0, 画面高 − 41)` の範囲へ丸める（`ui/ScribbleUi.java` の `keepBandOnScreen` が `BandLayout.WIDTH` / `HEIGHT` を使うので、定数を変えれば追従する）。範囲内なら位置は一切変えない
- 目的は、帯の幅が広がったことで、**旧バージョンで保存した右寄りの位置だと帯の右端にある終了ボタン＝出口が画面外に出てしまう**のを防ぐこと（ヒューリスティクス3）。0.4.0 で幅が 235 から 256 へ広がるので、同じ補正がそのまま効く。ドラッグ中に補正しないのは、掴んだ帯が指から離れないようにするため
- **利用者が帯を動かした結果、地図 MOD の部品（JourneyMap の下部ツールバー・右列・キー一覧、Xaero の方角表示等）と重なることは許す。可動範囲を部品の外に制限しない・自動で押し出さない・帯を前面に出さない。** プラン 08 の決まり 1 の上限（幅 264・高さ 41）と決まり 5 の重なりの禁止は、既定の大きさ・既定の位置 (28,44) についての決まりであり、AC5・AC111・AC124・AC126 で守る（08 の決まり 5「帯は利用者が動かせるが、既定の位置で重ならないことが前提」）。理由は、部品の位置が版・言語・設定で変わり MOD から分からないこと、置いた位置を勝手に変えると予測できなくなること（切替ボタンとの重なりを許した AC68・AC104 と同じ）、重なっても帯の余白をドラッグすれば戻せること。重なった部分は JourneyMap のボタンが帯の上に描かれる（`FULLSCREEN_RENDER_EVENT` がボタンより先に呼ばれるため）。（2026-11-18 追加。26.3 Fabric＋JourneyMap、GUI 320×240、bandY=186 付近で下部ツールバーと重なることが実機で分かったため）

#### 3.5.1 切替ボタンを動かす（2026-11-10 追加）

**利用者と困りごと。** CurseForge に届いた要望の原文: "is oit possible to move the pencil button along the x-why axis because he covering up the direction overlay on 1.20.1 xaeros map"。Minecraft 1.20.1 の Xaero's World Map で、右上の鉛筆ボタンが地図側の方角表示を隠している。隠れる物は地図 MOD・版・解像度で変わるので、MapScribble が固定の避け先を決めるのではなく、利用者が置き場所を決められるようにする。

**対象。** `ScreenMapHost` が自前で描くボタン、つまり Xaero's World Map・FTB Chunks・旧 JourneyMap（`JourneyMapLegacyAdapter`）の3つ。既定の位置は今までと同じで、**動かさない人には見た目も位置も変わらない**。

**操作（マウスの左右で分ける）**

| 操作 | 結果 |
|---|---|
| 左ボタンを押して、動かさず離す | 手書きモードの切替（今までどおり）。**切替の瞬間を「押した時」から「離した時」へ変える**（押した時点ではクリックかドラッグか決められないため） |
| 左ボタンを押したまま 4 画面ピクセル以上動かす | ボタンがカーソルに付いてくる。離すとそこへ置き、手書きモードは変わらない |
| Shift を押しながら左クリック（動かさず離す） | ボタンを掴む。ボタンを押していなくてもカーソルに付いてくる。**次の左クリックで**そこへ置く（ドラッグできない利用者のための手段。WCAG 2.5.7） |
| 右クリック | 元の位置（既定の位置）へ戻す。確認は出さない。すでに元の位置なら何も変わらない。**どちらの場合もクリックは地図へ渡さない** |
| 移動中に Esc（Shift+クリックで掴んだ時は右クリックも） | 移動を取り消し、動かす前の位置へ戻す。**Esc で地図の画面を閉じない。** 移動していない時の Esc は今までどおり |

**クリックとドラッグのしきい値: 押した点から、横か縦のどちらかが 4 画面ピクセル以上離れたらドラッグ。**

- 判定式: `max(|floor(現在のGUI x) − floor(押したGUI x)|, |floor(現在のGUI y) − floor(押したGUI y)|) × GUI倍率 >= 4`。両方を整数に切り捨ててから比べる（押した時の座標は小数、描画中の座標は整数で来るので、そのまま比べると動かしていなくても倍率が大きい時にドラッグになる）
- GUI ピクセルではなく画面ピクセルで決める理由: 手の震えは画面上の距離で決まり、GUI 倍率によらないため。結果は倍率1で 4 GUI px、倍率2で 2 GUI px、倍率3〜4で 2〜1 GUI px
- 判定は描画のたび（`ScreenMapHost.java:186-200` と同じ場所）と、離した時の両方で行う。1フレームの間に押して動かして離しても取りこぼさないため
- 一度ドラッグになったら、元の位置へ戻してから離してもドラッグのまま（切替にならない）
- 掴んだ点は保つ: ボタンの位置は `カーソル − 押した時のカーソルとボタン左上の差`。カーソルがボタンの中央へ飛び移らない

**位置の覚え方（近い端からの距離）**

- 離した時に、ボタンの中心が画面の左半分か右半分か、上半分か下半分かを決め、**近いほうの端からの距離**で保存する。右半分なら `dx = 画面幅 − 20 − x`、左半分なら `dx = x`。下半分なら `dy = 画面高 − 20 − y`、上半分なら `dy = y`
- 表示する位置は、保存値から毎フレーム計算する: 右なら `x = 画面幅 − 20 − dx`、左なら `x = dx`。y も同じ
- 地図 MOD のボタンや表示は画面の端に沿って並ぶので、端からの距離で覚えれば、GUI 倍率や窓の大きさが変わっても「方角表示の左隣」のままになる（例: 右上・`dx = 79` は、GUI 幅 960 で x = 861、幅 320 で x = 221。モックアップで確かめた）
- **地図 MOD ごとに別に覚える。** 避けたい物も既定の位置も地図 MOD ごとに違うため。キーは `xaero` / `ftb_chunks` / `journeymap_legacy`
- 保存先は既存の `config/mapscribble-ui.json`。形式は `"toggleButtons": { "xaero": { "right": true, "bottom": false, "dx": 79, "dy": 6 } }`。動かしていない地図 MOD のキーは書かない（キーが無い＝既定の位置）
- 置いた位置が既定の位置と同じなら、動かしていないものとしてキーを消す。右クリックで戻した時も同じ
- 保存は置いた時・戻した時の1回だけ。移動中は一時の座標だけを更新し、`DrawingState` の変更通知を出さず、ファイルへ書かない（毎フレームの書き込みを避ける。`rules/14-low-load.md`）

**画面の外へ出さない補正**

- 移動中も表示の時も、左上を x: 0〜`画面幅 − 20`、y: 0〜`画面高 − 20` に丸める。ボタンの全体が常に画面内にある（切替ボタンは出口でもあるため）
- **丸めた値を保存値へ書き戻さない。** 小さい画面で丸められても、大きい画面へ戻せば元の場所へ戻る（帯の補正 `ScribbleUi.java:148-157` は書き戻すが、切替ボタンは書き戻さない。端からの距離で持つので、書き戻すと一度小さくしただけで置いた場所を失うため）
- 設定ファイルの値が壊れている時（`toggleButtons` が物でない、`right` / `bottom` が真偽値でない、`dx` / `dy` が数値でない・負）は、その地図 MOD だけ既定の位置を使う。他の設定は読む。大きすぎる値は上の丸めで画面内に収まるので、エラーにしない

**ツールの帯と重なった時**

- 自動で押し出さない。重なりを許し、今までどおり**帯が手前に描かれ、重なった部分のクリックは帯が受ける**（AC68 を変えない）。右クリックも帯が受ける
- 押し出さない理由: 帯は手書きモード中だけ出るので、押し出すと置いたはずの位置がモードで変わる。帯の余白をドラッグすれば帯を動かせるし、手書きモードを終えて帯が消えれば切替ボタンをいつでも掴める。帯に覆われている間も、帯の終了ボタンが出口になる
- 移動中は切替ボタンを帯より手前に描く（掴んだ物が帯の下へ消えないように）。移動中は帯のホバーとツールチップ、メモのホバーを出さない。実装は、移動中だけ帯の描画へ画面外のマウス座標（−1, −1）を渡し、消しゴム・編集のホバー検索（`ScreenMapHost.java:211`）を行わない。入力は移動の処理が先に受けるので、帯へは渡らない

**見た目**（既存の色を変えず、新しい色を足さない）

**状態**

**推奨案の根拠と、落とした案**

依頼元の第一案（左ドラッグで移動、動かさず離せば切替）を採った。帯と同じ作法で覚える物が増えず（`ToolBand.java:118-123`）、上の AssistiveTouch と同じ形で、20×20 のボタンのほかに画面要素を足さない。足したのは、ドラッグ以外の手段（Shift+クリック）と、戻す手段（右クリック）である。

| 落とした案 | 理由 |
|---|---|
| 設定画面に X / Y の数値欄を作る（要望の "x-why axis" の字義どおり） | MOD に設定画面が無く、新しい画面を足すことになる。数値を入れては地図を開いて確かめる繰り返しになり、地図を見ながら置くドラッグに劣る |
| 設定ファイルの数値を手で直す | 操作は画面上の GUI で提供する方針に反する |
| 長押しで掴む | 待ち時間がある上に、いつ掴めたかの手掛かりを足す必要がある |
| ボタンの横に移動用の取っ手を付ける | 画面要素が増え、地図をさらに隠す。依頼に無い要素である |
| 戻す操作を Shift+右クリック・ダブルクリック・専用キーにする | 修飾キーは手が増えるだけで誤操作の害に釣り合わない。ダブルクリックは切替を2回行う操作と区別できない。専用キーは未割り当てが既定になり見つからない。右クリックは今のボタンに割り当てが無く、1回で届き、ツールチップで案内できる。誤って押しても置き直せば戻る |
| 画面幅に対する割合で覚える | 端に沿った物の隣に置いても、画面が変わると隙間が伸び縮みして、また重なる |
| 帯と同じく左上の座標そのままで覚える | 右上に置いた物が、GUI 倍率を変えると画面の中ほどへ離れる |
| 全地図 MOD で1つの位置を共有する | 避けたい物が地図 MOD ごとに違い、既定の位置も違う |
| 帯と重なったら押し出す | 上の「ツールの帯と重なった時」のとおり |

- Esc: 名前を変えている間は名前の変更の取りやめ。それ以外は画面を閉じて地図（手書きモードのまま）へ戻る（完了と同じ）

**画面の作り直しで保つもの（窓の大きさ・GUI の倍率の変更、確認画面からの戻り）**（2026-11-18 追加）

- 起きていること: 窓の大きさ・GUI の倍率を変えた時と、確認画面（「ここの分を移す」「見える分を移す」）から戻った時、バニラは画面の部品を全部作り直す（`clearWidgets` → `clearFocus` → `init` → `setInitialFocus`）。何もしなければ、最後の入力がキーボードだとフォーカスが一番上の部品（分ける切替）へ移り、一覧のカーソルとスクロールが捨てられ、名前の変更中なら入力欄が見えなくなって打った文字が消える（ボタンは「決定」「キャンセル」のまま残る）。2026-11-18 の実機（1920×1080・倍率2）でも、一覧で操作していたのに窓を変えた後はフォーカスが分ける切替に移り、最初の ↓ が一覧に効かなかった
- **メモ帳の読み込みの完了も、画面の状態を変える（2026-11-24 追加）。** 画面は開いている間、メモ帳の状態が変わった通知（読み込みの完了・切り替わり・記録の更新）を受け、受けたら主スレッドで行を出し直す（部品は作り直さない）。操作が無くても、読み込み中に開いた画面は読み込みの完了で「読み込んでいます…」から行の一覧へ変わる。通知の受け手は、画面を開いた時（`init`）に足し、離れる時（`removed`＝閉じる・確認画面へ移る）に外す。作り直し（窓の大きさの変更）では足し直さず、確認画面から戻った時は `init` で足し直す。行が替わっても、フォーカスと一覧のカーソル（行 ID）は下の表のとおり保たれる
- 決まり: **利用者はこの画面に何もしていないので、作り直しの前と後で、フォーカス・カーソル・入力・画面の状態が同じに見えるようにする**（作り直しを利用者に気付かせない）。作り直しの直前の値を覚え、作り直しの後に戻す

| 保つもの | 戻し方 |
|---|---|
| フォーカスのあった部品 | 部品は役目で対応づける（分ける切替・一覧・名前の入力欄・名前を変える／決定・新しいメモ帳／キャンセル・ここの分を移す／元に戻す・見える分を移す・完了）。**作り直しの前にどの部品にもフォーカスが無かったら、後も無しにする**（最後の入力がキーボードでも、バニラの初期フォーカスで分ける切替へ移さない）。フォーカスの枠の出方（キーボードで入った時に出る枠）も作り直しの前と同じにする |
| 一覧のカーソルの行 | メモ帳の id で戻す。その行が無くなっていたら範囲内へ丸める（「一覧の中身が変わった時」と同じ）。行を押せない間は、カーソルを描かないまま |
| 一覧のスクロール | 作り直しの前の位置を、新しい一覧の範囲（窓の大きさで 3行⇔6行が変わる）へ丸めて戻す。そのうえで、一覧にフォーカスがあればカーソルの行が、名前の変更中なら入力欄の行が、見える位置に収まるようにスクロールする（見えていれば動かさない） |
| 名前の変更中の入力 | 入力欄を同じ行に出したまま、打った文字・カーソルの位置・選んでいる範囲・入力欄へのフォーカスを戻す。下のボタンは「決定」「キャンセル」のまま、移す操作は押せないまま。検証の失敗の1行（y 125）が出ていれば出したまま。始めたボタン（「名前を変える」か「新しいメモ帳」。決めた・取りやめた後にフォーカスを戻す先）も覚えたまま |
| 画面の状態 | 移した後の白い行と「元に戻す」のボタン、移すのに失敗した時の赤系の行、移している間の灰色の行とボタンを押せない状態。作り直しで初期の表示へ戻さない |

- **確認画面から戻った時のフォーカス**: 「移す」「キャンセル」「Esc」のどれで戻っても、確認画面を開いたボタンへ戻す（「ここの分を移す」で移した後は、同じ場所で「元に戻す」に替わったボタン）。マウスで押して開いた時も同じボタンへ戻す（枠の出方は上の表のとおり作り直しの前と同じ）。一覧のスクロールも開く前と同じ
  - 移している間はボタンが全部押せない。戻す先のボタンにフォーカスを置いたまま（Enter は効かない）にし、移し終えたらそのボタンで Enter が効くようにする。バニラの作りで押せない部品にフォーカスを置けない場合は、移し終えた時点でそのボタンへフォーカスを置く
  - 移し終えた後に戻す先のボタンが押せない時（見えている分が 0 件になった等）は、Tab の順でその次の押せる部品（最後は「完了」）へ置く
- 3.7「キーボード」の「一覧から離れて戻った時は、前回のカーソルの位置は覚えない」は、利用者が Tab やマウスで一覧から離れた時の決まりであり、作り直しには当てはめない
- 根拠: 利用者の操作でないことで、打った文字を失ったり、効かない「決定」と見えない入力欄が残ったりするのは、利用者の制御の外で状態が変わる誤りである（NN/g「10 Usability Heuristics」の3「利用者の制御と自由」・5「誤りの防止」。2章の表の出典）。キーボードの利用者は、窓を変えるたびに Tab で元の場所までやり直すことになる。窓の大きさを変えても入力中の文字やフォーカスが消えないことは、OS の窓やブラウザで利用者が既に知っている振る舞いである
- 落とした案

| 落とした案 | 理由 |
|---|---|
| 作り直しで初期の状態に戻す（今の作り） | 上の「起きていること」のとおり。打った文字が消え、キーボードの利用者は操作の場所を失う |
| 名前の変更中に作り直しが起きたら、名前の変更を取りやめにする | 打った文字を失う。利用者は取りやめていない |
| 作り直しの後は、いつも一覧の使用中の行にフォーカスを置く | 一覧の外（完了・新しいメモ帳など）で操作していた利用者のフォーカスが、何もしていないのに動く |

### 3.8 分ける前のメモの見分け方（0.4.0）

**地図の見た目は変えない。** 分ける前のメモも、メモ帳のメモと同じ線・塗り・文字で描く（社長の指示「既定で隠さない」と、地図を煩雑にしないため）。見分ける手掛かりは、利用者がメモに触ろうとした時にだけ出す。

| 場面 | 出す物 |
|---|---|
| 消しゴム・編集でメモにホバーした時 | 今のツールチップ（「クリックで消す：<文字>」等）の下に、灰 `#A0A0A0` の2行目「分ける前のメモ（どのサーバーにも出ます）」 |
| 編集の画面（3.2） | 見出しの後ろに灰色で「（分ける前のメモ）」。行は増やさない（パネルの高さを変えない） |
| メモの保存先の画面（3.7） | 件数と、移す操作 |

- 出すのは「サーバーごとに分けている接続先」だけ。分けていない接続先・シングルプレイでは、すべてのメモが同じ扱いなので出さない
- 0.9.0 の「表示の設定」の候補に「分ける前のメモを隠す」（既定はオフ＝隠さない）を挙げる（その版で決める）

### 3.9 説明の行に出す新しいお知らせ（0.4.0）

**お知らせは2種類に分ける。**
- **操作の結果**（3.1 の一時のお知らせ8件と `msg.move_busy`）: 待たせず、出ているお知らせをすぐ置き換える。置き換えられたのが「起きたこと」で、まだ2秒未満しか出ていなかったものは、待ちの先頭へ戻す。
- **起きたこと**（3.9 の表の全キー。`move_busy` を除く）
  - 待たせるのは最大2件まで。3件目が来たら、一番古い待ちを捨てる。
  - 同じキー・同じ引数のものは足さない。
  - 帯が出ていない時に起きたものは、次に帯を出した時に1回だけ出す。
  - 帯が出ていない間は時間を数えない。
  - 接続を離れた時は待ちを捨てる。
- どちらも4秒表示し、最後の0.5秒で薄くなる。色はキーごとに表のとおり。

| キー | 出す時 | ja_jp | en_us | 色 |
|---|---|---|---|---|
| `mapscribble.msg.notebook_switched` | 使うメモ帳の id が、前と違う値（null でない）に変わった時。自動（分け始め・サーバーの移動・新しいサーバーでの自動作成・0.1.0 の取り込み）と、画面で選んだ時のどちらも。接続先に入った最初の決定を含む。ディメンションの移動だけ・直下へ替わった時は出さない。名前は表示名（空なら「（名前なし）」） | 使うメモ帳：%s | Notebook: %s | 白 |

## 9. アクセシビリティ要件

- 選択・状態を色だけで示さない: ツールは白縁＋説明の行の文字、色は白枠＋「色：<名前>」、メモの表示の切替は目の絵柄＋説明の行、文字の表示切替は斜線の絵柄＋ツールチップの文言、手書きモードのオンは青い面＋白い縁＋ツールチップ＋帯が出ていること、失敗は文字で内容を書く。**メニューを開いている間はボタンの青い面＋メニューが出ていること。使用中のメモ帳は青い面＋白い縁＋「［使用中］」の文字。押せない項目は灰色＋理由のツールチップ**（0.4.0）
- 文字のコントラストは 4.5:1 以上、部品の縁・アイコンは 3:1 以上（4 の計算値）。2026-10-26 に、基準を満たしていなかった切替ボタンのオフの縁（1.46:1）を `#A8ADB4`（4.6:1）に直した。2026-11-17 に、メニューのホバーの面・使用中の行・帯の灰色を、基準を満たす値へ決め直した（4章末）
- 文字入力の画面はキーボードだけで完結する（Tab・←→・Enter・Ctrl+Enter・Esc）。**メモの保存先の画面もキーボードだけで完結する**（Tab・↑↓・Enter・Esc。3.7）。**メニューも ↑↓・Enter・Esc で操作できる**（3.6。開くのはマウスで、帯の他の操作と同じ）
- **保存先の画面は、窓の大きさ・GUI の倍率の変更と確認画面からの戻りで、フォーカス・一覧のカーソル・名前の入力を失わない**（0.4.0・2026-11-18。3.7「画面の作り直しで保つもの」）。一覧の ↑↓ は行を押せない時もフォーカスを一覧の外へ出さず、一覧から出るのは Tab・Shift+Tab だけ（同「キーボード」）
- 帯の操作はマウスで行う（JourneyMap の全画面マップ自体がマウス操作のため）。ツールの切替（1〜5）・取り消し・やり直し・モードの切替はキーでもできる
- 押せる領域: 帯のボタン **18×18**（2026-11-17 変更。旧 20×20）、終了 18×35、太さ・文字の大きさ・塗り 16×13、色 8×13（GUI 倍率2で 2 倍の画面ピクセル）。文字入力の画面の色は 16×16。メニューの行は 150×14、保存先の画面のボタンはバニラの高さ 20、一覧の行は 282×14。GUI 倍率2 以上では帯のボタンが 36 画面ピクセル以上で WCAG 2.5.8 の 24 を満たす。**倍率1では 18 画面ピクセルで満たさない**（旧 20×20 でも同じ。最小の画面で帯を 264 幅に収めるための上限で、倍率1を選ぶ画面は GUI 座標が広いので、利用者は GUI 倍率を上げられる）
- **出口が画面外に出ない**: 帯を画面内へ収める補正（3.1 末尾）で、終了ボタンが常に画面内にある。切替ボタンも移動中・表示中とも画面内へ丸める（3.5.1）。メニューも画面内に寄せて開く（3.6）
- ドラッグでしかできない操作は「囲み」「線」を描くことと、帯を動かすこと（既存）。「囲み」「線」は描画そのもの。消す・直す・色や太さの変更・モードの終了はクリックでできる。**切替ボタンの移動はドラッグなしでもできる**（Shift+クリックで掴み、クリックで置く。WCAG 2.5.7）
- 切替ボタンの戻す・移動の操作は、ツールチップの文字で案内する。アイコンや色だけに頼らない（3.5.1）
- **戻せない操作を作らない**（0.4.0）: メモ帳の切替は元の行を押せば戻る、名前の変更はもう一度変えれば戻る、分ける切替はもう一度押せば戻る、移すは元に戻すで戻る。他のサーバーに出なくなる「移す」だけに確認を挟む

### 0.4.0 で落とした案

| 落とした案 | 理由 |
|---|---|
| 20×20 のボタンのまま並べる | 道具6・メニューを足すと幅 269〜273 で、上限 264 を超える |
| 消しゴムを編集の下段へ入れて道具を減らす | 消すたびに「編集→下段で消す」の1手が増える。消しゴムは描く間に繰り返し使う |
| 2つの表示切替（文字・メモ）を1つのボタンにまとめる | 別々の操作（文字だけ隠す／全部隠す）が、押すたびに3状態を巡る操作になり、今の状態と次の状態が読みにくい |
| 図形を4番目（文字の後）に置く | 消しゴム・編集の場所と既定のキー（4・5）がずれ、利用者が保存したキーの割り当てと場所が合わなくなる |

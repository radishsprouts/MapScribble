# MapScribble 画面設計（ツールの帯・文字入力の画面・地図上のメモ・文言・素材）

- 作業区分: community（無料運営のサーバー向けクライアント MOD。収益化の要素は入れない）
- 担当: Dev-UI-Designer（2026-10-20）
- 改訂: 2026-10-20 説明の行の文言を幅 190 以内に短縮し、切れた時の全文ツールチップと開発環境での幅の警告を追加（実機で「No notes yet. Drag around an area to…」と切れたため。3.1・6・8）
- 改訂: 2026-10-21 実装後のデザインレビューを反映。(1) 文字数カウンタはバニラの `MultiLineEditBox` に描かせ、左のヒントをその行（欄の下＋4）に揃える（MOD とバニラが2重に描いて読めなくなったため。3.2・AC40）。(2) ツールの切替キー 1〜5 を採用し、ツールチップの1行目にキーを添える（実装担当が JourneyMap 6.0.10 の操作一覧で数字キーが空いていることを確かめたため。3.1・6・AC13・AC57・11）。(3) GUI 320×240 で Keys がオンの時、キー一覧の上端が帯の右下に重なることが実機で分かった。AC5 の前提にした「キー一覧は右下」という見込みが誤りだったので、AC5 をこの場合だけ直した（3.1 の根拠・AC5・11）。(4) 文字入力の画面の幕を、親の画面より1つ上の描画の層に塗る（3.2）
- 改訂: 2026-10-26 手書きモードの終了ボタンを帯の右端に追加し、右上の切替ボタンをオンの時も常設のトグルにした。文字の表示切替の対象を「囲みの文字だけ」から「すべての文字」へ広げ、文字メモには印を残すことにした。帯の大きさを実装に合わせて **235×41**（2段＋帯の外の説明の行）に改めた（3.1・3.3・4・6・7・8。詳細は `fix-toggle-and-text-visibility.md`）
- 改訂: 2026-10-27 実装後の未決2件を決めて反映。(1) `text_visible` / `text_hidden` の枠は点線（点 1px・間隔 1px）で確定（7章・AC79）。(2) 文字メモの印の「対角 8 画面ピクセル」は**縁を含まない本体の寸法**で、`MARK_RADIUS` は 4 のまま（3.3・4・AC73）。(3) 帯を画面内へ収める補正を設計として認めた（3.1 末尾・AC83〜85）
- 元になる章: プラン `03-操作と画面.md`・`05-JourneyMap連携と描画.md`
- モックアップ: `docs/design/ui-mockup.html`（1 GUI ピクセルを 2 CSS ピクセルで表示。ブラウザで開く）。終了ボタンと文字の表示切替は `docs/design/mockups/fix-toggle-and-text-visibility.html`

単位はすべて **GUI ピクセル**（Minecraft の GUI 倍率を掛ける前の座標）。例外は地図上の線の太さで、これは JourneyMap の `ShapeProperties.setStrokeWidth` に渡す値（画面ピクセル）で書く。

## 1. 目的・利用者・主要タスク

- 利用者: 無料サーバー（一般 `lis_world`・資源 `res_world`）で JourneyMap を使っているプレイヤー本人。メモは自分にだけ見える
- 主要タスク
  1. 全画面マップで手書きモードにして、区画をなぞって囲み、文字を付ける（主機能）
  2. 線を引く・文字だけを置く
  3. 描いたメモを消す・直す・元に戻す
  4. メモ全体を一時的に隠す／地図上の文字だけを一時的に隠す
- 動線: 全画面マップ（JourneyMap）→ 右列の「手書き」ボタン（またはキー）→ ツールの帯が出る → 描く → 文字入力の画面 → 確定で地図へ戻る → 帯の終了ボタン（または右上/右列の手書きボタン）でモードを終える

- ゲーム内の実機の画面は、この役職の権限（ブラウザのみ）では見ていない。寸法・位置は実装（`ui/BandLayout.java`）と、実機で測った記録を根拠にしている

### そこから採ったこと

- 右列は JourneyMap と他のアドオンのボタンが増える場所、上部・下部・左は JourneyMap の固定のボタンと表示行。**MapScribble の帯は、そのどれにも触れない左上の「上部ツールバーと表示行の下、左列の右」に置く**
- アイコンは JourneyMap に合わせて**白い単色の線画・透過**にし、状態の色はプログラムで乗せる
- 地図上の囲みは MapFrontiers と同じ「実線＋半透明の塗り＋中央の文字」にする（利用者が知っている見え方）
- アイコンだけにしないため、帯の最下段に**選択中のツール名と操作の説明を常に文字で出す**（ツールチップだけに頼らない）
- 表示切替は JourneyMap の作法に合わせ、**1ボタン＝その種類の全部**にする（文字の表示切替は、囲み・線・文字メモのすべての文字が対象。2026-10-26）

## 3. 推奨案

### 3.1 ツールの帯（手書きモード中だけ表示）

**置き場所: 画面の左上、既定の原点 (x=28, y=44)、大きさ 235×41。** 説明の行は帯の外（帯の左上から (3,44)、`HINT_Y = Y + 44`）に描く。**利用者は帯の余白をドラッグして動かせ、位置は保存される**（`ui/ToolBand.java:116-150`）。ドラッグしていない間は画面内へ収める補正が掛かる（この節の末尾）。

根拠:
- Minecraft は GUI 座標が 320×240 未満にならないよう倍率を選ぶ。最小の 320×240 で、JourneyMap の各要素は次の範囲にある（実測からの見込み）。帯 (28..263, 44..85) は、キー一覧を除くどれとも重ならない
  - ロゴ: x 0..22, y 0..22 / 上部ツールバー: 中央、y 0..22 / 表示行: y 約24..34
  - 左列: x 0..24、縦中央（240 の時 y 約78..162）→ 帯は x 28 から
  - 右列: x 296..320 → 帯の右端 263（33px の余裕）
  - 下部ツールバーと表示行: y 206..240
  - キー一覧（Keys オン時）: 右下。**GUI の幅が 427 以上なら帯に届かない。幅 320（窓 640×480・倍率2）では、下部ツールバーを避けて上へ伸び、上端が y 約91・左端が x 約205 まで来る**（2026-10-21 に実機の画像で確かめた。行の数と幅は JourneyMap の版と言語で変わる）。**帯の高さが 57 から 41 になり下端が y 85 になったため、重なるかどうかは実機で測り直す**（未決事項。11章）
- `FULLSCREEN_RENDER_EVENT` は**ボタンより先に**呼ばれる（05章）。重なると JourneyMap のボタンが帯の上に描かれてしまうので、ボタンと重ならないことが必須
- 縦に並べる案は、最小の画面で高さが足りない（全要素で 200 を超える）ため落とした。色・太さを押して開く小窓にする案は、色を変えるたびに1手増え、小窓が左列に重なるため落とした

**説明の行の長さ**

- 説明の行に出る文言（`mapscribble.hint.*` 5件・`mapscribble.msg.*` 12件）は、ja_jp・en_us とも **幅 190 GUI px 以内**で作る（行の幅 202 から 12 の余裕。和文は全角1字 9px で上限を見積もる）。各キーの幅は 6章末の表
- それでも「…」で切った時（リソースパック・利用者が作った他言語の翻訳）は、マウスが説明の行の範囲 **x = 帯の 3〜205、y = 帯の 43〜53**（画面座標では HINT_X〜HINT_X+202、HINT_Y−1〜HINT_Y+9）にある間、全文をバニラのツールチップ（白・1行。長ければバニラが折り返す）で出す。切っていない時は出さない。ボタンのツールチップとは範囲が重ならない
- **開発環境だけの幅の警告**: 最初に帯を描く時に上の17件の `font.width` を測り、190 を超えたものがあれば、`FabricLoader.getInstance().isDevelopmentEnvironment()` が真の時だけ、キー名と幅を警告ログに1回出す（本番では測らない）

**状態ごとの帯の振る舞い**

- 読み込み中・地図の準備中・読み込み失敗: ツール・色・太さは押せる（選んでおける）が、地図への描画・消しゴム・編集のクリックは何もしない（地図の移動も止めない＝ドラッグを取り消さない）。元に戻す・やり直すは無効。**終了ボタンと右上/右列の切替ボタンは、どの状態でも有効**
- メモを隠している時: 囲み・線・文字は描ける。**新しいメモを確定したら自動で表示に戻す**（描いたのに見えない、を防ぐ）。消しゴム・編集のクリックは「メモを表示してから選んでください」を出して何もしない
- 文字を隠している時: 囲みの輪郭・塗り・線はそのまま出る。文字メモは菱形の印になる（3.3）。描く・消す・直すはいずれも通常どおりできる
- 権限なし: この MOD はクライアントだけで自分のメモを扱うため、権限で操作を分ける場面は無い（サーバーの権限チェックも無い）

**帯の位置と、画面内への補正**（2026-10-27 追加。詳細と落とした案は `fix-toggle-and-text-visibility.md` 3.8）

- 帯は余白をドラッグして動かせ、位置は保存される。既定は (28,44)
- **ドラッグしていない間だけ**、帯の左上を x: 0〜`max(0, 画面幅 − 235)`、y: 0〜`max(0, 画面高 − 41)` の範囲へ丸める（`ui/ScribbleUi.java:144-157`）。範囲内なら位置は一切変えない
- 目的は、帯の幅が 208 から 235 へ広がったことで、**旧バージョンで保存した右寄りの位置だと帯の右端にある終了ボタン＝出口が画面外に出てしまう**のを防ぐこと（ヒューリスティクス3）。ドラッグ中に補正しないのは、掴んだ帯が指から離れないようにするため

**見出し**: 新規「囲みのメモ」「線のメモ」「文字のメモ」、編集「囲みのメモを編集」「線のメモを編集」「文字のメモを編集」

**ボタン**
- 確定: メモを追加（新規）または変更（編集）して閉じる。取り消しの履歴に1件積む
- キャンセル: 新規なら**描いた形ごと取り消して**閉じ、帯に「描いたメモを取り消しました」。編集なら何も変えずに閉じる

**キー操作**
- Esc = キャンセル、Ctrl+Enter = 確定（文字のメモで空欄なら何もしない）、Enter = 改行
- Tab / Shift+Tab のフォーカス順: 文字の欄 → 色の見本（10個で1つの止まり場所。←→で色を選ぶ）→ 塗り → 文字の大きさ → ミニマップ → 削除 → 確定 → キャンセル
- 開いた時のフォーカス: 文字の欄（すぐ打てる）。フォーカス中のバニラのボタンは白枠（バニラ既定）

## 9. アクセシビリティ要件

- 選択・状態を色だけで示さない: ツールは白縁＋説明の行の文字、色は白枠＋「色：<名前>」、メモの表示の切替は目の絵柄＋説明の行、文字の表示切替は斜線の絵柄＋ツールチップの文言、手書きモードのオンは青い面＋白い縁＋ツールチップ＋帯が出ていること、失敗は文字で内容を書く
- 文字のコントラストは 4.5:1 以上、部品の縁・アイコンは 3:1 以上（4 の計算値）。2026-10-26 に、基準を満たしていなかった切替ボタンのオフの縁（1.46:1）を `#A8ADB4`（4.6:1）に直した
- 文字入力の画面はキーボードだけで完結する（Tab・←→・Enter・Ctrl+Enter・Esc）
- 帯の操作はマウスで行う（JourneyMap の全画面マップ自体がマウス操作のため）。ツールの切替（1〜5）・取り消し・やり直し・モードの切替はキーでもできる
- 押せる領域: 帯のボタン 20×20、終了 20×35、太さ・文字の大きさ 16×13、色 8×13（GUI 倍率2で 2 倍の画面ピクセル）。文字入力の画面の色は 16×16
- **出口が画面外に出ない**: 帯を画面内へ収める補正（3.1 末尾）で、終了ボタンが常に画面内にある
- ドラッグでしかできない操作は「囲み」「線」を描くことだけで、これは描画そのもの。消す・直す・色や太さの変更・モードの終了はクリックでできる
